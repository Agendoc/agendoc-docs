# WhatsApp (parte 3): plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** mandar pelo WhatsApp (Cloud API da Meta, número de teste) a "Consulta marcada" com a triagem e os lembretes, só para contas de teste com "WhatsApp de envio".

**Architecture:** na API, um pacote `whatsapp` no molde do `mail`: `WhatsAppGateway` (Cloud API via `RestClient`, ou só log quando não configurado), `WhatsAppService` que envia depois do commit no `mailExecutor`, e um enum `WhatsAppTemplate` que lê o texto de cada template de `resources/whatsapp/` (o mesmo texto que o autor cadastra na Meta), usado para medir o limite de 1.024 caracteres e para o log de desenvolvimento. Um `WhatsAppNotifier` monta as mensagens; os lembretes ganham o canal `WHATSAPP` na tabela da parte 2 e o `ReminderJob` escolhe o envio pelo canal. Na web, um campo no Perfil e o Switch na confirmação.

**Tech Stack:** Spring Boot 4.1 / Java 21 / MySQL 8.4 / Flyway / Testcontainers, `RestClient` + `MockRestServiceServer` (sem dependência nova) · Next.js 16 / React 19 / Vitest / MSW.

**Spec:** [`../specs/2026-11-16-whatsapp-design.md`](../specs/2026-11-16-whatsapp-design.md). Leia o spec antes. Este plano só registra as decisões de implementação.

## Global Constraints

- **Branches:**
  - Integração: `feat/whatsapp`, criada a partir de `develop` em `agendoc-api` e `agendoc-web`.
  - Uma branch por tarefa (`feat/whatsapp-NN-*`), juntada com `--no-ff` na integração quando os gates estiverem verdes.
  - Commits semânticos, curtos, em inglês, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - Nunca `main` ou `release` sem pedido do autor.
- **Gates:**
  - API: `JAVA_HOME=~/.asdf/installs/java/temurin-21.0.11+10.0.LTS ./mvnw verify` verde a cada tarefa.
  - Web: `npm run ci` verde a cada tarefa. Nunca rodar `npx prettier`.
- **Camadas:** `controllers/<f>`, `command/<f>/inputs|outputs`, `services/<f>`, `entities`, `repositories`. Swagger só nos controllers. Código em inglês, interface e mensagens em pt-BR. Poucos comentários.
- **Migrações:** Flyway só aditivas, a partir de `V10`.
- **Valores fixos do spec:**
  - Contas de teste: `paciente1..3@demo.agendoc.dev`. Só elas têm `deliveryWhatsapp`.
  - Templates da categoria utility, idioma `pt_BR`, corpo preenchido com no máximo **1.024** caracteres.
  - Variáveis sem quebra de linha, sem tab e sem mais de 4 espaços seguidos; nunca vazias (a Meta recusa): vazio vira `—`.
  - "Ver consulta": `https://agendoc.duckdns.org/consultas/{id}`. "Como chegar": `https://www.google.com/maps/search/?api=1&query={endereço codificado}`.
  - Lembretes: mesmos horários e regras da parte 2 (até 4 falhas, atraso máximo de 10 min).
- **Variáveis de ambiente:** cada nova vai em `application.yml` (`agendoc.whatsapp.*`), no `.env.example` e no `deploy/compose.yaml`:

  | Variável | Padrão |
  |---|---|
  | `WHATSAPP_PHONE_NUMBER_ID` | vazio |
  | `WHATSAPP_ACCESS_TOKEN` | vazio |
  | `WHATSAPP_API_VERSION` | `v27.0` |
  | `WHATSAPP_LANGUAGE` | `pt_BR` |
- **Logs:** nunca registram o token nem as variáveis das mensagens em produção. O número aparece mascarado (só os 4 últimos dígitos). O gateway de log (sem configuração) pode mostrar a mensagem montada.
- **Web:** segue o DS (`agendoc-web/CLAUDE.md`). Usa `src/components/ui` primeiro e estiliza só por tokens.

## Review Focus

- **Meta recusando o envio** (número fora da lista do painel, token vencido, template não aprovado): marcar responde 201, o e-mail sai igual, o lembrete soma tentativas até `FAILED`, e o token não aparece no log (testes nas Tarefas 1 e 4).
- **Texto livre torto na triagem ou no endereço** (quebras de linha, tabs, muitos espaços, relato vazio ou enorme): as variáveis saem achatadas, nunca vazias, e o corpo preenchido fica em até 1.024 caracteres (testes nas Tarefas 1 e 3).
- **"WhatsApp de envio" apagado depois de marcar:** os lembretes `WHATSAPP` pendentes viram `SKIPPED`; os de e-mail continuam (teste na Tarefa 4).
- **`whatsappReminder` vindo de conta comum ou de conta de teste sem número:** marca normalmente, sem linhas `WHATSAPP` e com `whatsappReminder:false` na resposta (teste na Tarefa 4).
- **Os dois canais com os mesmos horários:** cada canal envia uma vez, `reminderOffsets` da consulta não repete horário, e a remarcação copia os dois canais (teste na Tarefa 4).

**Interfaces (produzidas):**
- `record WhatsAppProperties(String phoneNumberId, String accessToken, String apiVersion, String language, String baseUrl)` em `agendoc.whatsapp` (`baseUrl` padrão `https://graph.facebook.com`, só para testes) com `boolean configured()` (ID e token não vazios).
- `record WhatsAppMessage(String to, WhatsAppTemplate template, List<String> bodyParams, List<String> buttonParams)`: `to` só dígitos (`5511912345678`); `buttonParams` na ordem dos botões de URL do template.
- `interface WhatsAppGateway { void send(WhatsAppMessage message); }`:
  - `CloudApiWhatsAppGateway`: `POST {baseUrl}/{apiVersion}/{phoneNumberId}/messages` com `Authorization: Bearer`, corpo `{"messaging_product":"whatsapp","to":…,"type":"template","template":{"name":…,"language":{"code":…},"components":[{"type":"body","parameters":[{"type":"text","text":…}…]},{"type":"button","sub_type":"url","index":"0","parameters":[{"type":"text","text":…}]}…]}}`. Timeouts: conexão 5 s, leitura 10 s. Resposta não 2xx vira `WhatsAppException(int status, Integer metaCode)` (o `error.code` do JSON da Meta, quando houver); a mensagem da exceção nunca leva o token.
  - `LoggingWhatsAppGateway`: `log.info` com o template, o número mascarado e `template.render(bodyParams)`.
  - `WhatsAppConfig` cria um ou outro conforme `configured()`.
- `enum WhatsAppTemplate { BOOKED("agendoc_consulta_marcada"), BOOKED_TRIAGE("agendoc_consulta_marcada_triagem"), REMINDER("agendoc_lembrete") }` com `metaName()`, `body()` (lido de `classpath:whatsapp/<metaName>.txt`, criado na Tarefa 3) e `render(List<String> params) -> String` (troca `{{n}}`).
- `WhatsAppText.param(String value, int max) -> String`: troca qualquer sequência de espaços em branco (inclui `\n`, `\t`) por um espaço, apara, corta em `max` com `...` no fim, e devolve `—` se ficar vazio.
- `WhatsAppService.send(WhatsAppMessage)`: igual ao `EmailService` (depois do commit, no `mailExecutor`, nunca propaga). Falha: contador `agendoc.whatsapp.failures` e `log.warn` com template, número mascarado, status e código da Meta.
- `CapturingWhatsAppGateway`: `static List<WhatsAppMessage> sent()`, `static void clear()`, `static void failNext()`, `static void failAlways(boolean)`.
